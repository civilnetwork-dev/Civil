## Prisma: category requests, policy and native companions

The signed `background.js` is 6,313,199 bytes, SHA-256 `0c48c87fa736ccf5a2100c1c8681a3de5359c8025f430ee9c94b2db1d9beb4c0`. Vendor rotation functions and bootstrap code are never executed. `prismaBrowser/decoding.json` records both hashes; `background.decoded.txt` retains the reading copy. Unresolved computed calls remain separate.

The legacy Webroot path `_0x4624b0`, near decoded lines 59285–59326, builds `https://classifier.talon-sec.com/getinfo?url=…`. It accepts an HTTP-success response only when parsed body `status` equals numeric 200 and `results` exists, then caches it. `_0x1cead4` strips the query, or the fragment when no query exists, before the legacy lookup. These returned categories are not an organization-specific allow/block verdict.

The AUF function `_0x399033`, near decoded lines 59650–59865, requests `https://classifier-auf.talon-sec.com/url/lookup/talon?url=…`. It obtains or mints a JWT, sends `X-Talon-Signature`, `X-Talon-TraceId` and `X-Talon-Integrity`, and can verify an RSA response signature and response freshness/URL relation. The selected replay proves that no lookup occurs without a token; HTTP 401 causes token refresh with at most two lookup attempts; a false success field or network rejection returns no result. Signature/freshness acceptance was inspected statically, not proved against a real vendor response. No cloud lookup was sent.

The decoded URL-filter setup selects AUF/Webroot providers and installs navigation/request listeners for main and child frames; pre-login policy evaluates a separate WebAccess directive. Thus a category result alone cannot stand in for active policy, login state or enforcement. Native messaging includes `com.panw.pab.content_scan` and `com.paloaltonetworks.peconfigmanager`. Those host implementations and their device policy are outside the extension artifacts examined here.

`auth.talon-sec.com`, its regional/staging counterparts, `idm.talon-sec.com` and region-composed IDM hosts provide authentication/identity paths. `gateway*.talon-sec.com` also carries `/endpoint-auth/auth/login`; a `/sentry` telemetry string on a gateway does not justify rejecting the entire host. Region-composed gateway, assets, feature-flag and private-application services have additional roles. Preserve functional authentication traffic; classifier-host discovery is not proof that Civil controls a privileged extension's requests.

## Dyknow: supplied classroom rules and privileged redirects

`worker.js` imports the application and lifecycle services. `js/mjs/settings.js` sets the core server to `https://api.dyknow.me/` and authentication server to `https://oauth.dyknow.me/`. The OAuth client posts to `oauth/authenticate` with device/account context; the satellite client receives a runtime `baseUrl` and uses SignalR for broadcast/classroom commands. No public anonymous reputation endpoint or real tenant decision was established.

`js/mjs/cabra/helper/urlFilter.js` maintains teacher allow/block arrays and global exceptions. With a supplied allowlist, unmatched URLs are filtered; otherwise supplied block entries apply subject to global exceptions. `redirectTab` publishes a block event, retains the original tab and calls the privileged tab update API with the configured redirect, defaulting to `https://studentontask.com`. The replay verifies supplied allow/block cases, a global exception, malformed input and that redirect. It does not contact the teacher service or establish which policy a real class supplies.

`studentontask.com` is a policy-redirect surface, not a hostname-rating API. OAuth and core/satellite services carry authentication and classroom traffic together; their availability alone is not evidence that a destination was classified as a proxy. The source also contains activity collection and application-block services. Remaining teacher-session, screenshot, direct-control and satellite branches require representative state and are not reconstructed by the seven URL-policy assertions.

## ClassLink: analytics endpoints and functional SSO

Analytics+ `cl-analytics-api.js` sends identified app/domain launch, activity and close events under `/launch/v1p1/lp/…` and `/launch/v1p1/url/…`, and anonymous events under `/anonLaunch/v1p0/…`, to `analytics-events.apis.classlink.com` or `beta-analytics-events.apis.classlink.com`. Configuration controls anonymous/incognito/IP tracking. Login state and attribution notes select the account context; the API is not a category or enforcement contract.

The exact wrapper replay exercises production/beta host selection, query/body serialization, a synthetic `gws` authorization header, HTTP 200/201/401, non-JSON text and network rejection. Only HTTP 200 sets its wrapper's success field; even non-JSON 200 text has that field. A network rejection yields status zero. These wrapper facts do not turn a response into a policy verdict.

OneClick's background module 430 sends app usage events to `analytics-log.classlink.io` or `analytics-log-beta.classlink.io`, with `/launch/v1p0/launch` and `/activity/v1p0/activity` or `/activity/v1p0/close`. The separate SSO worker/content paths receive launch tasks, wait for target navigation, validate top-level domains and deliver provider-specific form/task operations. The shipped host expressions include LaunchPad, login, MyApps, teacher-console, backpack and EU frontends. Broad host blocking of ClassLink would break these functional paths; dedicated analytics hosts are separable.

`detection.js` adds a hidden `sCLExtInstalled` node on a `browsersso/` URL and records version 12.7. This is an SSO extension marker, not evidence that Civil was classified or blocked. No password values, real launch payload or SSO account was collected. Civil's requested Sign in with ClassLink integration is separate backend work; the extension's form SSO mechanisms are not an OAuth client implementation.
